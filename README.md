# LLM 배포 게이트

LLM이 만든 산출물을 배포 직전에 원본 데이터와 대조해, 어긋나면 그 자리에서
멈추게 하는 코드입니다. 주식·경제 콘텐츠 파이프라인에서 운영 중인 모듈을
그대로 떼어 왔습니다.

```
python -m pytest tests/ -q
78 passed, 1 skipped
```

## 왜 만들었나

LLM으로 금융 콘텐츠를 만들면 세 가지 실패가 남습니다.

- 숫자 왜곡
- 방향 오류. 하락을 상승으로 씁니다
- 원본에 없는 고유명 생성

셋 다 문장은 멀쩡해 보입니다. 그래서 눈으로는 못 잡고, 배포되면 회수가 안
됩니다. 건수가 늘수록 사람이 전수 확인하는 방식은 무너집니다.

모델 품질을 올리는 것으로는 못 막습니다. 모델은 계속 좋아져도 틀릴 확률이
0이 되지는 않습니다. 그래서 배포 직전에 산출물을 원본과 기계적으로 대조하고,
불일치가 하나라도 있으면 예외를 던져 멈추게 했습니다. 사람의 주의력 대신
구조에 걸었습니다.

## 두 모듈

### `gates/qa.py` — 숫자 원본대조

카드와 낭독, 제목에 쓰인 숫자·방향·문구가 원본 스냅샷에서 파생된 신호와
전수 일치하는지 독립 검증합니다. `hard_fail` 이 하나라도 있으면 업로드를
차단합니다.

검증 항목입니다.

- 금액 표기 왕복. 억·만원 문자열로 바꿨다가 다시 파싱해 원본과 정확히 일치하는지
- 제목·낭독에 카드와 동일한 금액 문자열이 들어 있는지
- 방향(▲▼)이 실제 이벤트와 모순되지 않는지
- 해제된 거래를 배제했는지
- 비교 표본수 표기가 원본과 같은지
- 표본이 적을 때 단정 표현을 쓰지 않았는지
- 고유명이 원본에 근거하는지. 추정 정보를 만들어 내지 않는지

```python
from gates.qa import assert_publishable

assert_publishable(signal, title=title, narration=narration)
# 하드 실패가 있으면 RuntimeError 를 던지고 업로드가 없다
```

### `gates/qa_codes.py` — 게이트 코드 레지스트리

사유 문자열과 분류 규칙의 단일 진실 원천입니다. 게이트 18개가 등록돼 있고
각각 코드, 매칭 패턴, 분류, 실제 사유 예시를 가집니다.

이 모듈이 왜 필요한지는 사고에서 나왔습니다. QA 결과는 한국어 문장
리스트이고, 업로드 게이트의 강등 판정은 그 문장에 정규식을 겁니다. 즉
**게이트 메시지 문구를 한 글자 바꾸면 강등 분류가 조용히 깨집니다.**
2026-07-11 에 등급 패턴이 인용 본문에 오발화하는 사고가 있었습니다.

그래서 코드와 패턴과 예시를 한곳에 모으고, 테스트가 패턴과 실제 메시지의
대응을 검사합니다. 문구가 바뀌면 조용한 오분류 대신 테스트 실패로 드러납니다.

레지스트리에 없는 사유는 `unmapped` 을 돌려주고 **하드 실패로 남습니다.**
분류를 모르면 통과시키는 게 아니라 막는 쪽이 안전한 방향입니다.

## 심각도는 둘뿐입니다

등급을 셋 이상으로 쪼개 보니 아래 등급을 아무도 안 봤습니다. 그래서 둘로
줄였습니다.

| 분류 | 처리 |
|---|---|
| 하드 실패 | 사실이 틀린 것. 예외를 던져 그 자리에서 멈춥니다 |
| 경고 | 품질이 아쉬운 것. 기록만 남깁니다 |

경고를 띄우고 사람이 판단하게 하는 방식은 쓰지 않습니다. 사람은 경고를
무시하고, 하드 실패와 섞으면 둘 다 무시하게 됩니다.

자막 싱크는 강등 목록에 없습니다. 하드로 유지합니다. 이 경계가 무너지면
싱크 불량이 통과하기 때문이고, 테스트가 그 경계를 지킵니다.

## 실제로 무엇을 막았나

운영 로그에서 업로드 직전 중단이 37건 잡혔습니다. 사유별로는 주체 누락 115,
제목 키워드가 본문에 없는 경우 93, 낡은 지수 등락률 41 순입니다.

가장 위험했던 건 방향 오류입니다. 로그에 남은 문구 그대로입니다.

```
동일 엔티티 방향 카드/대본 불일치: 나스닥(카드=up/대본=down)
동일 엔티티 방향 카드/대본 불일치: 엔비디아(카드=down/대본=up)
opener 방향이 기사/본문과 반대: 엔비디아
```

화면의 카드는 상승이라고 하는데 낭독은 하락이라고 말하는 상태입니다.
각각은 멀쩡한 문장이라 한 화면씩 검수해서는 안 잡힙니다. 그래서 검수 단위를
화면이 아니라 엔티티로 바꿨습니다. 같은 종목이 카드와 대본과 제목에서 같은
방향을 말하는지를 봅니다.

차단 건수는 셌지만 차단율은 세지 않았습니다. 분모를 같은 기준으로 집계하지
않아서입니다.

## 공개 범위

운영 저장소에서 게이트 로직과 테스트만 떼어 왔습니다. 운영 데이터, 채널
식별자, 자격증명, 프롬프트 본문은 포함하지 않습니다.

`gates/formatting.py` 는 원 저장소에서 카드 렌더러가 소유한 헬퍼 중
QA가 쓰는 것만 옮긴 것입니다. 색상값은 판정에 쓰이지 않아 자리표시자입니다.

드리프트 검사 한 건은 건너뜁니다. 실제 게이트 구현 파일이 운영 저장소에만
있어서입니다. 테스트는 지우지 않고 조건부로 두었습니다.
